# Antigravity 连接

Lagoon 通过 **SSH 设备**接入开发机上的 Antigravity CLI 原生 ACP 接口（`agy acp`）。Antigravity 是设备上的独立 Harness，与同一设备上的 DSH、OpenCode 和 Codex 共享 SSH 连接与主机指纹，彼此的开关、草稿与会话完全独立。

## 准备与添加

1. 在开发机的目标用户环境中安装支持 `agy acp` 的 Antigravity CLI，并在该用户的终端运行 `agy acp --login` 完成登录。Lagoon 不接收 Google 密码或登录令牌。
2. 在 Lagoon 中添加 SSH 设备并核对主机指纹，在设备详情页点击「刷新发现」，再添加 **Antigravity**。只读发现只检查 `agy` 命令存在及 `agy acp --help` 支持 ACP，实际登录态与会话可用性以连接后结果为准。开发机需要 POSIX shell、SFTP 和 Python 3，`agy` 必须在登录 shell 的 PATH 中。AGY 1.5 的会话列表只返回第一个工作目录，Lagoon 会只读查询该用户 AGY 目录数据库以识别其他工作区；数据库或 Python 不可用时不会声称按目录筛选的列表完整。
3. 在 Antigravity 连接内添加开发机上已存在的绝对工作目录，再打开已有会话或创建新会话。项目目录由 SSH SFTP 验证，不会自动创建远端目录。

## 能力与边界

- 可浏览会话和历史，创建并继续会话，发送文本及受支持的图片，查看流式文本、思考与工具输出，并按当前会话提供的选项选择模型和思考强度。模型目录由会话协商，空白草稿在创建会话前不推测可用模型。
- 工具审批使用 AGY 实际提供的选项 ID；支持的结构化提问为单层字符串表单。停止请求发出后，最终状态以 AGY 的轮次结果为准。
- AGY 可能把额度耗尽等提示作为普通文本返回，同时将轮次标为 `end_turn`；Lagoon 保留上游结果并显示提示文字，不从文案推断失败状态。
- 工作区文件浏览和文本预览经 SFTP realpath 校验并限制在工作区内（只读）；当前不提供 AGY 文件搜索与应用内终端。
- `agy acp` 进程跟随 SSH 通道；断线或关闭连接可能中断正在执行的轮次，不保证后台继续执行。
- AGY ACP 没有可供本客户端验证的全局活动会话清单，其他客户端或旧连接发起的任务状态不会被推测为已结束。当前没有会话重命名、归档、删除、分叉、回退、压缩和斜杠命令接口。
