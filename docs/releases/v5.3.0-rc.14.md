## 本次更新

- **SSH 连 DSH 不再「只探测到 Harness、一个对话都没有」**：根因是这台电脑上已经跑着 `dsh web`
  （桌面版、命令行或另一台手机启动的都算）时，Lagoon 会直接放弃并报「已有 DSH 服务，但无法安全
  复用」。DSH 本身支持多实例，每个进程有独立令牌和端口，这条拒绝既没必要也把最常见的使用状态
  一刀切了。现在 Lagoon 只管理自己记录的那一份，别人的实例不参与、也不会被停止。
- **过期记录按「过期」处理，不再当成冲突**：进程退出、重启后 PID 被复用、日志里没有启动链接、
  改过启动命令、目录权限被放宽，都会自动启动新的一份；只有状态目录是符号链接或属于别的用户时
  才拒绝并给出处理方式。自己那一代进程若能证明身份（PID + 启动时间），会先正常结束再重开，
  不留孤儿进程。此前一旦卡住，用户只能自己上电脑删 `~/.lagoon-ssh-dsh` 才能恢复。
- **不再要求远端安装 Python 3**：启动锁改为带持有者 PID 的锁目录，进程被杀死时等待方立即接管，
  跨客户端互斥仍然成立。首次启动的等待上限从 60 秒提高到 180 秒（`dsh web` 首次运行要初始化
  `~/.dsh/profiles/web`），因此新机器第一次连接不再报「启动超时」。
- **失败不再假装在重试**：缺少 dsh、状态目录不可用、主机密钥变化这类重试也不会好的失败，现在
  停在失败状态并显示完整原因（含要在电脑上做什么），不再每 60 秒重来一次、也不再被「60 秒后
  重试」盖住；Harness 详情页新增「SSH 连接状态」，带失败原因和「重试」。
- **隧道身份校验每代只做一次**：此前每条 HTTP 连接都要在远端起一个 `python3`、扫一遍 `/proc`
  并额外发一个请求，DSH 一次并发四个读就会碰到 25 秒读超时并占用 sshd 会话。现在每代连接校验
  一次，后续连接直接复用已证明的代次；远端缺 `python3`/`lsof` 时降级为「启动记录校验」并在诊断
  里说明，不再让整条链路不可用。
- **远端 `dsh web` 换了进程会自己恢复**：令牌轮换后不再只是报「正在重新获取启动令牌」却没有
  动作；保活每分钟比对一次记录的进程代次，端口相同但进程换代也会重新读取令牌。
- **SSH 下的会话功能补齐**：`SshDshClient` 是手写的转发层，漏掉了 `searchSessionContent`、
  `serverWorkspaces`、`forkSession(boundary)`，而能力声明仍然声称支持——表现为会话全文搜索、
  工作区管理、按历史边界分叉在 SSH 下点了没反应。现已全部转发，并加了一条反射回归测试：
  以后 `HarnessClient` 新增方法而 SSH 层没转发，测试会直接失败。
- **首轮读取不再一处失败整页空白**：能力探测和会话目录读取失败时会退回上一次的能力表或后台
  监控已拿到的会话列表，而不是把整页清空；空列表页会直接显示失败原因，按钮也从「新建会话」
  改回「重新连接」。
- **连接与网络层**：每个 SSH 绑定使用独立连接池（OkHttp 判断连接能否复用时不比较
  `SocketFactory`，共享池可能把一条隧道里已认证的连接交给另一个 loopback 监听）并强制
  `Proxy.NO_PROXY`；读超时 25 秒提高到 60 秒、单次调用预算 90 秒，`$events` 就绪窗口在隧道上
  放宽到 45 秒。添加 SSH Harness 时若当前没有选中服务器，会直接连上去，不再「添加完什么都不
  发生」。

- **SSH 连 OpenCode 也能看到状态、失败和原因了**：此前只把「注册文件存在」当成探测成功，
  服务退出后仍显示「已发现」；连接失败又被总览吞掉，首页只剩空列表，首次连接还要等满
  240 秒才报错。现在探测会同时确认 `opencode` 的路径与版本，并对注册里的本机端口发一次
  有上限的 `/api/info`，把「服务未运行 / 认证失败 / 注册过期 / 不是 2.x」分开说明；注册文件
  属于其他用户或任何人可写时拒绝使用，同组可写会提示 `chmod 600`。首次连接失败立即给出
  原因，服务重启后自动重读注册再试，不必手动「刷新发现」。
- **新增 OpenCode ACP 连接**：`opencode acp` 在 1.x 与 2.x 都有，直接在这条 SSH 上跑一个
  ACP 进程即可列会话、读历史和发消息，不需要常驻服务、注册文件、端口转发或 Python。
  它与「OpenCode」是两条独立的 Harness，可以同时添加；能力以 ACP 为准（没有归档、删除、
  分叉、终端这些原生 HTTP 才有的动作）。
- **失败可见、可恢复**：首页和 Harness 详情会显示 SSH 失败原因并支持重试；OpenCode 详情页
  新增「启动或重启服务」（用户点击才执行，探测永远只读）。

## 验证

- 全量单元测试 **1903 项、0 失败**（22 项按环境跳过）；`:app:testDebugUnitTest :app:assembleDebug`
  通过。改动前的 `main` 在本机是 1874 项、3 项 SSH 用例失败（本机 `umask 0002` 让自建状态目录
  变成 group-writable，被当成「不可信」）。
- 新增回归用例：`anotherClientsDshWebNeverBlocksOurOwnInstance`（同用户在跑的 `dsh web` 存在时
  仍能启动自己的实例、且不向它发信号）、`bootstrapReplacesUnverifiableGenerationWithoutSignallingIt`
  （无启动时间的活进程按过期处理且不被信号）、`SshClientForwardingTest`（SSH 转发层遗漏方法即
  失败）、`SshProofDegradeTest`（缺 python3 时降级、明确判定他人 socket 时仍拒绝）。
- 行为变更的旧用例已按新策略更新：`legacy` 记录不可验证时改为「忽略并启动自己的实例」，不再
  报冲突。
- OpenCode 侧新增：发现存活/失联/注册过期/非 2.x/权限过宽的解析用例、死服务快速失败
  （`deadRegisteredServiceFailsFastInsteadOfHoldingTheReader`）、注册向前兼容、服务启动动作
  的命令形状，以及 `opencode acp` 的探测/命令校验与可选的真 sshd 回归（`SshOpenCodeAcpIT`）。

## 已知限制

- 本机没有 Android 真机执行环境，SSH 模组只在 JVM 里用假 transport 与本地 shell 验证；仍需在
  真机上对一台**已经跑着 `dsh web`** 的电脑完整复测「添加 → 连接 → 出现会话 → 断开重连」。
- 每代一次的 socket 属主证明是安全与可用性的折中：同一代连接内不再逐连接复核，长时间运行的
  代次依赖保活每分钟比对进程代次。
- 远端 `python3`/`lsof` 缺失时只做启动记录校验，理论上弱于 socket 属主证明；诊断里会保留提示。
- OpenCode ACP 的**发送**没有跑出成功轮次：验证机上 `opencode` 的所有模型都报
  `provider.no-route`（用 `opencode run --model …` 独立复现，与本版本无关），因此只证明了
  初始化、会话列表与历史回放；方法名与参数已被服务端接受。
- OpenCode 的「启动或重启服务」依赖 2.x CLI 的 `opencode service status/start/restart`；1.x
  会被拒绝并提示需要 2.x（ACP 路由不受此限）。
- 本版本为预发布版本（`pre-release`），按 GitHub 规则不会标记为仓库首页 Latest。
