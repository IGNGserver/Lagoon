## 本次更新

- **会话归档恢复可用**：OpenCode 从 2.1.0 起用会话更新接口顶层的 `archived` 布尔表示归档（`false` 即取消归档），此前按旧假设只认一个并不存在的 `time.archived` 字段，导致连上任何真实服务器时「归档」入口都被隐藏、点了也只会报「服务器未提供归档」。现在读取实例自身的接口描述即可正确判断，会话菜单里的归档 / 取消归档按服务器真实契约收发。
- **排队消息可以插话、撤回和编辑**：会话运行中排队的消息，长按菜单此前一律提示「此服务器不支持修改排队消息」。现在「立即插话」会把该条切成插话、在下个步骤边界执行，「撤回」直接取消，编辑则按官方语义先把原附件读回来、撤回后以排队身份重新入队，附件不会丢。
- **worktree 会话不再指向不存在的目录**：会话的工作目录本来就已经包含子路径（`subpath` 只是它相对项目根的标签），此前又拼了一次，worktree 里的会话会被算成 `/repo/wt/wt` 这类并不存在的路径，连带文件浏览、附件引用与位置相关请求都打偏。现在一律使用服务器给出的真实工作目录。
- **别处归档会立刻反映**：桌面端或终端把会话归档 / 取消归档后，手机首页与会话状态实时跟上，不用等下一轮全量同步；在别处分叉出的会话也会立即出现在列表里。
- **几处请求细节对齐官方**：手动压缩带上客户端生成的 id，重复点击不会排入两次压缩；会话上记录的模型选择改用官方字段名，其他客户端也能正确读到；「运行中会话」的解析收敛到服务器实际返回的形状；改动列表在补丁被截断时给出明确提示，不再读一个永远不存在的字段。

顺带新增了一份从上游 OpenCode v2.2.6 原样摘录的接口契约样本，归档与相关路由的形状直接跑真实契约做回归，避免再按设想写测试。

## 已知限制

- 尚未在真实 OpenCode 2.x 实例上复核观感与联动，需要在设备上过一遍：归档与取消归档、桌面端归档后手机是否即时消失、运行中排队消息的插话 / 撤回 / 编辑（含带附件的那条）、以及 worktree 会话里的文件浏览。
- OpenCode 2.0.x 服务器本身没有归档接口（2.1.0 才加入），在这些版本上归档入口仍然不会出现；这是服务器的能力边界，不是缺陷。
- 会话的元数据、权限规则、用量统计等事件本版本仍未投影到界面（应用侧没有对应状态），只有归档、分叉与运行状态会实时更新。
- 本版本为预发布版本，不会标记为 GitHub Latest；需要首页可见的 Latest 标记时，应以正式版类型重新发布。
