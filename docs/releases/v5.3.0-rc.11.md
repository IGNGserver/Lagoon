## 本次更新

- **扫码配对中断后可以接着做**：先核对电脑上报的服务器地址，确认后才向该地址发送配对请求；电脑端显示 8 位验证码，输入正确后手机才保存凭据，验证码界面开启防截屏。配对途中切后台、关闭面板或应用被重启后再打开，会接着上一轮继续，而不是重头再来；配对超时或会话已失效时会提示到电脑端重新生成二维码。
- **重新登录能接回原来的电脑**：同一中枢退出后重新登录，账号本身与每台电脑的授权分别恢复，已固定的主机指纹按原值校验；登录态失效不再静默丢掉设备。多个中枢和账号分开列出，从设备详情进入管理时带的是这台设备所属的中枢。
- **受限账号按服务端说明处理**：扫码授权属于普通账号还是只能管设备的账号，以服务端返回的结果和本机记录为准，不再按账号名猜测；刷新多台设备时分别核对，个别设备核实失败只影响它自己，界面保留上一次记录并给出提示。
- **设备状态不再含糊**：离线、登录失效和发现不完整分别标注，部分结果不会覆盖尚未重新确认的记录；在线状态先显示为待确认，只有近期中枢观测或实际连接才能说明它在线。
- **删除与撤销说得更清楚**：「退出登录」保留本机缓存并停止后台重连，「删除中枢」才清掉设备、指纹和离线缓存；删除单台设备只撤销这一条关系，同一手机身份仍被其他设备使用时保留共享身份。需要联网才能完成的远端撤权会记录下来继续尝试，并区分「本机已移除」「待撤销」「已撤销」。
- **断线恢复更可靠**：远程会话重连后补齐内容，处理传输超时和消息缺口；审批或消息提交后结果无法确认时，先提示核对远端状态，不自动重发。后台压缩任务按中枢、账号、电脑和会话分别跟踪，重连后继续，投递状态未知的操作不会重复提交。
- **SSH 验证码逐项输入**：服务器要求额外验证（含一次性验证码）时按提示逐项填写，回答只用于本次连接，不保存、也不会自动套用已存密码；首次信任与指纹变化各有独立确认，指纹变了必须先重新信任才能连。
- **SSH 发送凭据前先验身份**：连接 DSH 或 OpenCode 前，先确认远端回环端口上真正持有 socket 的正是注册的那个进程（Linux 上同时处理 IPv4-mapped 监听 socket），验证通过才发送令牌、Cookie 或密码；本机转发端口同样带进程内随机接入凭据。
- **SSH 启动不再被锁卡住**：托管状态目录改到 `~/.lagoon-ssh-dsh/`，启动过程被中断后锁会被释放，不会让后续启动一直等；旧版本目录只读兼容，不会被本版本改写。
- **SSH 保存后可选择性检测**：表单区分「保存并检测」和「仅保存设备配置」，检测逐项显示各 Harness 的结果与失败原因，部分失败保留为未知而不是伪装成没装；同时修正了超时、取消与并发处理，旧检测结果不会覆盖新状态。

## 已知限制

- 本次没有 Android 真机或目标 SSH 主机：扫码、8 位验证码、指纹确认、防截屏与跨网络重连仍需在实机上逐项验收。
- SSH 模式下 DSH/OpenCode 的身份校验需要远端 Python 3；macOS 还需 `lsof` 和读取进程信息的权限。Windows 原生 cmd/PowerShell 的 SSH 模式暂不支持，可用 WSL 或其他接入方式。
- 远端撤权需要联网：设备离线时撤销会延后，期间该授权可能仍然有效；应用会保存待处理状态并在恢复连接后重试。
- 本版本为预发布版本（`pre-release`），按 GitHub 规则不会标记为仓库首页 Latest。
