## 本次更新

- **设备、接入源与 Harness 分成三层**：一台机器就是一台设备，DSH / OpenCode / Codex 是这台设备上的 Harness。设备列表按「由中枢管理 / 由 SSH 管理 / 直连」分组，一台设备一行。
- **设备页**：一个设备级开关，加上这台设备上的 Harness 列表。停用设备后不再为它建立中枢或 SSH 连接，也不做发现；Harness 自己的开关原样保留。停用某一条 Harness 只影响它自己，不拨号、不订阅、不推送，也不刷新缓存。
- **Harness 详情**：通知、新会话默认值、模型显示和协议专属面板（DSH 主机扩展、模型密钥、服务商，Remote 网络诊断）收进各自详情，设备页只留设备级设置。
- **添加设备只剩一个入口**：页内分「经由中枢」和「经由 SSH」，两条路都产出同一种设备。从中枢接入时可以勾选主机并核对指纹，**不再默认启用 DSH**；SSH 表单不再预选 Harness，保存时也不连接或启动远端服务。
- **发现改成显式动作**：设备页先显示上次的只读发现结果并标注是否过期，点「刷新发现」才连一次；设备停用时直接拒绝。中枢与 SSH 的发现共用同一套结果。
- **设备组按设备选**：把设备放进组即可，之后在这台设备上新启用的 Harness 会自动进入分组；设备暂时没有任何 Harness 时分组也保留。
- **SSH 接入源开关去掉**：一台 SSH 配置就是一台设备，设备开关是唯一门禁；旧数据里停用的 SSH 接入源会把意图下移到对应设备。
- **计数修正**：首页与设备页的「N 台设备」按机器计，不再把同一台机器上的多个 Harness 算成多台设备。

## 已知限制

- 尚未在物理 Android 设备、已登录的真实账户、生产 Remote 中枢或真实断网条件下做交互验收。
- 中枢「已采纳设备」依赖本机注册过的设备身份或已确认的主机指纹；极早期、身份记录缺失且没有任何 Harness 的主机可能需要重新接入一次。
- 设备组升级后按设备保存（v3）；旧分组成员会在第一次打开分组编辑器时回填，未回填的旧成员仍按原 leaf 归属生效。
