## 本次更新

- **一个 Host，多个 harness**：连接来源、Host 与具体 harness 现在分成三层。同一个服务器或同一个 Remote Host 上可以同时启用 OpenCode 和 DeepSeek Harness，各自独立开关；组合、分组和重叠引用都保留，不会因为启用一个而挤掉另一个。
- **SSH 自动发现**：连上 SSH Host 后会识别上面实际可用的 harness，并允许分别启用，不再需要手填一套绑定。
- **Remote 原生多 harness**：Remote 中枢可以按 Host 原生服务建立连接，能力和版本在连接时协商；不支持的接口会明确显示为不支持，而不是静默失败或换一条路径重试。
- **原生能力补齐**：DeepSeek Harness 侧补上工作区登记管理、服务器正文搜索、指定历史事件分叉、终端、Diff 与定时任务；OpenCode 侧补上历史消息分叉、项目元数据与 worktree 生命周期、原生长文本终端。各能力仍然按协议区分，不互相冒充。
- **安全与可靠性**：所有原生写入改为一次性发送，丢响应、401、408、503 或 `Retry-After` 不会自动重发；分叉、工作区、worktree 等非幂等操作在结果未知时会锁定原 Host 与原对象，必须先只读核对再由你明确确认。worktree 删除会真正移除后端目录，默认非强制，服务器要求强制时只提示、不自动升级。
- **资料不丢**：升级不会清空已保存的服务器资料、凭据、草稿、缓存、任务状态或设备分组；凭据保存过程在中途失败时会按日志恢复到已确认状态，不会出现“内存里成功、磁盘上没写”的假成功。
- **界面统一**：首页范围、Host 管理、原生能力面板和会话内操作按同一套连接身份组织；旧路由、旧客户端或已变化的项目/会话不会被迟到的结果改写。

## 已知限制

- 本版本为预发布版本，不会标记为 GitHub Latest。
- 没有连接 Android 真机：界面布局、无障碍、通知和预测式返回尚未在真机复核。
- 没有公网 Hub 和生产 Host 凭据：异网、丢包和真实公网环境尚未验收。
- DeepSeek Desktop 的 SSH 附着缺少上游支持的 IPC / Host attach 接口，暂不支持；macOS、Windows 和受限 proc namespace 上的原生 Host 归属证明会明确返回 `IDENTITY_UNVERIFIED` 并拒绝，而不是放行。
- OpenCode 基线契约没有提供会话正文搜索（`session?search=` 只是标题匹配），本版本不会把它冒充成 DSH 式正文搜索。
