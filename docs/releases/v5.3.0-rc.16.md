## 本次更新

- **DSH 升级后不再复用过期的托管实例**：Lagoon 在远端托管的 `dsh web` 过去只按进程号与启动时间复用，DSH 升级后旧进程仍会继续服务，却读不了新版本写入的会话日志（例如 `team/mode` 事件），打开会话会直接报错。现在启动/复用前会核对 dsh 安装指纹，只在确属 Lagoon 启动的旧进程上自动重启；自定义启动命令保持原有复用规则。
- **会话日志版本不匹配时给出可读说明并自动重连**：遇到旧实例读不了新日志时，不再把英文协议原文贴给用户，而是说明原因并自动重连设备；重连后会重启托管实例，会话恢复可读。
- **首页刷新只有一个状态来源**：下拉刷新、提示条重试、前台恢复、空页重新连接共用控制器里的同一份刷新状态，并发刷新不会叠出第二个转圈；刷新真正结束后才收起指示器。
- **删除“刷新已结束、后台仍在刷新”的假提示**：过去刷新超过 15 秒会弹“仍在刷新，完成后会自动更新”，且提示出现时指示器已经停下。现在慢刷新只把指示器文案改为“仍在刷新…”，不会再出现前后矛盾。
- **刷新中不再显示可点的“下拉重试”**：刷新进行中时，“部分数据待同步 / 下拉重试 / 点按刷新”一类提示整条隐藏，避免转圈和“点我刷新”同屏。
- **首页连接提示合并为一条**：连接阶段、登录/配对恢复、离线缓存、待同步最多只显示一条，按“传输失败 > 登录恢复 > 连接阶段 > 离线缓存 > 待同步”取最高优先级。
- **OpenCode 服务未运行时可在首页一键启动**：注册文件还在但进程已退出时，首页提示直接提供“启动服务”，不再只给无效的“重试”。
- **其他修复**：单设备视图不再丢失传输失败原因（以前只有聚合视图能看到红色错误）；离线空页点“重新连接”会真正发起重连，而不是刷新一个并不存在的连接。

## 已知限制

- 安装指纹按可执行文件（跟随符号链接后）的路径、修改时间与大小判断；若某种安装方式只替换被引用的嵌套包而入口文件不变，理论上仍可能漏判升级（比旧行为更安全）。
- 只有默认 `dsh web` 启动命令绑定安装版本；自定义 wrapper 命令仍按原来的进程记录复用。
- BSD/macOS 的 `stat` 分支只在 Linux 上用兼容 shim 验证，未在真实 macOS 上跑过。
- 首页新状态条与下拉文案只做了 JVM 单元测试与源码级回归，尚未在 Android 真机上点验。
- 本版本为预发布版本（pre-release），按 GitHub 规则不会标记为仓库首页 Latest。
