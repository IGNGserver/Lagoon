## 本次更新

- 会话缓存：OpenCode 会话改用本机 SQLite 缓存保存服务器返回的原始消息（加密存储，只保存已结束的消息）。旧缓存在升级后自动清除，之后按新方式重建。
- 打开会话更快：已缓存的会话先立即显示，再只读取最新一页并与缓存核对，只追加新增消息；网络差时不再依次请求多页。弱网基准（每请求 300 ms，工具调用密集的会话）：旧实现约 2000 ms、6 次请求、114 KB；无缓存首次打开约 830 ms、2 次请求；再次打开无新消息约 350 ms、1 次请求、9 KB。
- 一致性保证：核对失败（水位消息被撤销、顺序不一致、或新增过多读不到水位）时丢弃并重建该会话缓存；服务器改写已缓存消息时按服务器内容更正。
- 离线翻阅：离线时可以继续翻阅本机保存的历史消息，不需要连接服务器。
- 每周完整比对：在不计流量的网络下，约每 7 天对一次会话缓存做整段比对，不一致则丢弃重读。
- 设置 → 关于与诊断：显示会话缓存占用，可「清除会话缓存」；复制的诊断信息包含缓存统计（首次 / 校验通过 / 更正 / 重建 / 完整校验）。
- 同步提示文案改为「正在同步最新消息…」。

## 已知限制

- 尚未在 Android 真机或模拟器上验证：缓存的实际打开速度、设置页的缓存条目、离线翻阅的交互、以及升级后旧缓存的清除。
- DeepSeek Harness 会话不使用新缓存（其协议每次打开都下发完整快照），仍为原有的快照缓存。
- 每周完整比对只在不计流量的网络下运行，未在真实环境中观察其频率与耗时。
- 服务器改写早期消息的情况只能由完整比对发现，打开会话时不检查。
